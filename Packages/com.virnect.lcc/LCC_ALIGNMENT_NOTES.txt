✅ 표준 LCC 작업 단계 (2026-05-12 확정, 절대 손대지 말 것)
============================================================

Stage 1 : .lcc 폴더 드롭 → 자동 import + GaussianSplatAsset(Quality=High) 빌드 + 씬 spawn
Stage 2 : X 축 -90° 회전 + Freeze Transformations (Maya 와 동일)
Stage 3 : 사용자 박스(Cube) 기준 Z 축 회전만 fit (position/scale 금지, 다 000)


------ Stage 1 — 자동 import 파이프 ------

  .lcc 폴더 드롭 (Assets/LCC_Drops/)
     → LccDropAutoImporter   (AssetPostprocessor 자동 발동)
     → LccConverter          (splat-transform → .ply 임시)
     → GaussianAssetBuilder  (Aras-P GaussianSplatAsset 빌드, Quality=High)
     → 활성 씬에 자동 spawn:
         Splat_<name>             (Z-up→Y-up 회전)
           ├─ __LccCollider       (MeshCollider, proxy mesh, Z-up→Y-up 변환된 mesh,
           │                       world identity)
           └─ _ArasP              (GaussianSplatRenderer + asset, world identity)
     → Hierarchy 자동 선택 + ping

  Quality = High :
    PSNR    : 57.77 dB
    Compress: 2.94×
    Position: Norm16
    Scale   : Norm16
    Color   : Float16 × 4
    SH      : Norm11
  → 이 프리셋 외로 만들지 말 것 (디테일 깨짐 / 색 어긋남 발생).

  Packages/manifest.json 의 com.virnect.lcc 경로는 사용자 환경에 맞게 수정.
  예: "file:C:/Users/<USER>/path/to/com.virnect.lcc"


------ Stage 3 — 사용자 박스(Cube) 기준 Z 축 회전 fit ------

  씬의 Cube GameObject 를 컨테이너로, 각 ArasSplat_* 을 박스 안으로 정렬.

  철칙 :
    localPosition : 절대 건드리지 말 것 — 항상 (0, 0, 0)
    localScale    : 절대 건드리지 말 것 — 항상 (1, 1, 1)
    허용 변경     : localRotation 의 Z 축 회전 0° 또는 ±90° 단 하나만

  판정 (Cube 의 긴 horizontal 축이 Z 인 경우, 우리 데이터):
    scan world X > Z  → localRotation = (0, 0, 90)
    아니면            → localRotation = (0, 0, 0)

  제외 : 앵커로 쓸 스캔이 있으면 fit 에서 제외하고 identity 유지 (LccCubeFitter.s_Excluded).

  메뉴 :
    Virnect/LCC/📦 Fit ArasSplats into Cube
       회전만 결정/적용, position 항상 (0,0,0)
    Virnect/LCC/📦 Fit ArasSplats into Cube (refine)
       회전 유지하면서 position 만 (0,0,0) 재핀
    Virnect/LCC/📦 Reset ArasSplats to Frozen (Stage 1)
       Stage 2 frozen identity 로 되돌리기

  주의 : Fit 연속 호출 시 이미 회전된 splat 의 bounds 가 swap 되어 보여서
         회전이 풀리는 케이스 있음. 항상 Reset → Fit 순서로 호출.
  스케일 fitting (박스에 *완전히* 들어가게) 는 디테일 손실 동반.
  명시 요청 없으면 추가 X.


------ Stage 2 — X 축 -90° + Freeze Transform (Maya 와 동일) ------

Maya 의 "Freeze Transformations + Delete History" 와 동일한 결과 만들기.
다음 2-단 구조를 강제:

  __ArasRoot                            ← localRotation = (-90, 0, 0)    [Z-up→Y-up]
  ├── ArasSplat_Scan_A_Cutter      ← pure identity (Frozen child)
  ├── ArasSplat_Scan_B_Facility01     ← pure identity
  ├── ArasSplat_Scan_C_Facility04     ← pure identity
  ├── ArasSplat_Scan_D_Facility05     ← pure identity
  ├── ArasSplat_Scan_E_Facility06     ← pure identity
  └── ArasSplat_Scan_F_Middle ← pure identity

  __ArasRoot 의 transform     : (0,0,0) / (-90,0,0) / (1,1,1)
  ArasSplat_<name>.transform : (0,0,0) / (  0,0,0) / (1,1,1)   ← 완벽 identity

왜 두 단? Maya Freeze 는 회전을 vertex 좌표에 굽어버린다.
aras-p GaussianSplatAsset 의 position bytes 를 직접 재인코딩하는 것도 가능
(Wigner-D SH 회전까지 다시 짜야 함, 비용 큼) — 같은 사용자 효과
(= ArasSplat_ 의 Inspector 가 identity) 를 wrapper hoist 로 즉시 달성.
Maya 에서 "group → freeze group" 으로 동일 효과 내는 패턴과 같음.

구현 : Packages/com.virnect.lcc/Editor/LccArasSetup.cs
        → 'Virnect/LCC/🎬 Wire up aras-p Gaussian Splats' 메뉴가
          위 transform 을 자동 적용. 기존 GO 가 이미 있어도 매번 덮어씀.

검증 : 2026-05-12 스크린샷 — 공장 바닥 + 컨베이어 디테일 정상,
         거꾸로/옆으로 누운 현상 없음. ArasSplat_ 의 Inspector 모든
         transform 필드가 깨끗하게 0 / 0 / 1 로 표시됨.

손대지 말 것 :
  화면이 거꾸로 보이거나 옆으로 누우면 transform 으로 "고쳐" 두지 말고
  GaussianSplatAsset 의 Splat-PLY 가 Z-up (XGrids 기본) 으로 export
  됐는지 점검 → 아니면 converter 옵션 고치고 .asset 재생성.


정합 v2 — 핵심 결론
====================

🚨 LCC 파일 안에는 inter-scan 정합용 메타데이터가 **공식적으로 없음**.

근거 (XGRIDS LCC 공식 whitepaper 2025-11 + 우리 binary 분석):

  - mf_epsg = 0                                       (6개 전부)
  - mf_offset = mf_shift = [0,0,0]                    (6개 전부)
  - mf_scale = [1,1,1]                                (6개 전부)
  - xform_pos = [0,0,0], xform_rot = identity         (6개 전부)
  - poses.T_first ≈ (0,0,0)                           (6개 전부)
  - data.bin tail u24 : norm_mean ≈ 0.87 (SH DC 추정) — 정합엔 무관
  - reserved [26..32) = 0                              (6개 전부)
  - index.bin chunk index (x|y<<16) → 각 scan 이 자기 (0,0)부터 시작
  - mf_guid / task_id / attr_guid 는 단순 UUID — cross-scan 매핑 안 함

XGRIDS 공식 LCC whitepaper 도 "no multi-scan registration" 명시.
